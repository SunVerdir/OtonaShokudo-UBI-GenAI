## 1. このプロジェクトについて

**OtonaShokudo-UBI-GenAI** は、政策形成AI・行政DX・地域福祉・地域経済を横断し、

- 「誰一人、食から排除されない」地域インフラ
- 行政エッセンシャルワーカーの事務負担軽減
- 住民・地域事業者・行政の信頼できる資金循環
- 個人情報を過度に集中させないデータ設計
- 人間が最終判断を担う Human-in-the-Loop
- 監査可能なAI活用
- 将来的なフィジカルAIとの接続

を、一つの政策実装アーキテクチャとして整理するためのリポジトリです。

本プロジェクトは、単なる「AIチャットボット」や「給付アプリ」を目指すものではありません。

> **食を公共的な接点に、AIを事務負担軽減の道具に、監査台帳を信頼の基盤に、地域経済を循環させる。**

この考え方を、政策提言 → プロトタイプ → 実証 → 効果測定 → オープンな知見共有、という反復可能な形に落とし込みます。

## 2. 背景：なぜ「大人食堂」なのか

地域には、子ども食堂、フードバンク、社会福祉協議会、自治体窓口、医療・介護、商店・飲食店、農林水産業など、多様な「生活を支える現場」があります。

一方で、現場では次のような負担が重なります。

- 受付・記帳・集計・報告
- 助成・寄付・食材等の管理
- 広報・案内文書の作成
- 関係機関との情報連携
- 支援実績の確認
- 担当者間の引継ぎ
- 個人情報を扱う際のアクセス管理
- 限られた人員での継続運営

そこで、生成AIを「判断者」ではなく**下書き・要約・検索・記録整理を担う業務支援者**として位置付けます。

人間が承認・確認する工程を残しながら、定型的な事務をAIで軽量化することで、職員や現場スタッフが本来の対人支援・地域調整に時間を戻せる状態を目指します。

## 3. GENIAC-PRIZEとの接続

2026年度のGENIAC-PRIZEテーマ1は、「エッセンシャルワーカーの人手不足解消に資するAIを活用した業務プロセス改革」です。対象はAIシステムだけに限定されず、センサーやロボティクス等のフィジカル技術との連携も対象とされています。

また、テーマ1では国産基盤モデルを活用した開発・実証が応募要件として示されています。

本プロジェクトでは、**GIPU提供のGGUF軽量量子化モデル（Gemma系／Qwen系等をベースとする独自量子化モデル）**を候補基盤として、地域現場の限られた計算資源でも運用可能な生成AI環境を検討します。

### 想定するAIの役割

| 業務 | AIの役割 | 最終責任 |
|---|---|---|
| 日報・記録 | 要約、構造化 | 職員・担当者 |
| 広報 | 告知文・SNS文面の下書き | 職員・担当者 |
| 帳票 | 入力補助・下書き | 職員・担当者 |
| 会議記録 | 議事要約・論点整理 | 職員・担当者 |
| 問合せ対応 | 回答案の下書き | 職員・担当者 |
| 監査 | 記録の照合支援 | 監査担当・職員 |
| 政策形成 | 論点整理・比較表・草案 | 政策担当者・住民 |

**AIは決裁者ではありません。**

重要な判断、給付・支援の可否、例外処理、対外的な確定情報の発信等は、人間が確認・承認する設計を基本原則とします。

GENIAC-PRIZEの2026年度テーマ1では、応募締切が2026年9月30日12:00、成果物提出が11月末と案内されています。実証では「AIを導入した」ことではなく、ユーザー業務がどう変わったか、どの程度負担が減ったか、どのような安全性・監査性を確保したかを測定します。

## 4. 大人食堂（UBI）の政策仮説

### 4.1 食を「生活保障の入口」にする

大人食堂を、単なる食事提供施設ではなく、

> **食 → 相談 → 情報 → 地域サービス → 仕事・参加 → 地域内循環**

へ接続する「生活のハブ」と捉えます。

ここでいうUBIは、特定の給付制度を既成事実化するものではなく、**普遍的な生活保障を地域実装へ接続する政策仮説**として扱います。

制度化にあたっては、財源、対象、給付方法、既存制度との関係、所得再分配、自治体間格差、行政コスト等を別途検証します。

### 4.2 「現金だけ」ではなく「選択肢」を増やす

現金給付、食事、食材、地域ポイント、相談、学習、就労支援等を組み合わせ、

**住民が自分の生活状況に応じて選択できる公共サービス**

を目指します。

## 5. 源内モデル

本プロジェクトにおける「源内」は、デジタル庁が公開する生成AI利活用基盤「源内（GenAI）」から着想を得ています。

デジタル庁の源内Webは、行政職員が業務特化型の生成AIアプリケーションを迅速・安全・簡単に利用できる環境として公開されています。

本プロジェクトでは、その思想を地域の生活支援・政策形成へ展開します。

### 「源内」の役割

1. **読む** — 大量の記録・資料を要約する
2. **整理する** — 情報を項目・論点・課題に構造化する
3. **書く** — 帳票・広報・議事録等の下書きを作る
4. **つなぐ** — 関係者が必要な情報を見つけやすくする
5. **残す** — 判断に至った過程を監査可能な形で記録する

ただし、

> **生成AIの出力を、そのまま行政判断に採用しない。**

これを本モデルの重要な安全原則とします。

## 6. プライバシー・監査設計

### 6.1 氏名を持たない識別

個人を直接識別する氏名等をシステム内部の主キーとして常用するのではなく、用途に応じた**ハッシュ等の仮名化識別子**を利用する構成を検討します。

ただし、ハッシュ化だけで個人情報性が消滅するとは限りません。

したがって、

- データ最小化
- アクセス制御
- 権限分離
- 保持期間の制御
- ログ管理
- 再識別リスク評価
- 委託先管理
- インシデント対応

を含む総合的なプライバシー設計を行います。

### 6.2 監査台帳

「誰が、いつ、何を入力し、AIが何を生成し、誰が確認し、何を採用したか」を追跡可能にする監査台帳を設計します。

AI利用ログと業務上の確定記録を分離し、

- AI生成物
- 人間による修正
- 承認
- 取消・訂正
- 外部公開

を区別できるようにします。

### 6.3 「二重監査」への発展

将来的には、

**モノの流れ**
- 食材
- 配食
- 在庫
- 配送

と、

**カネの流れ**
- 寄付
- 助成
- 給付
- 地域内消費

を別々に記録し、必要な範囲で照合できる「モノとカネの二重監査」へ発展させます。

## 8. FDE（Forward Deployed Engineer）的な実装方法

本プロジェクトでは、完成品を一度に作るのではなく、**現場の課題を発見 → 小さく実装 → 現場で使う → 測定 → 改善 → 再利用可能な知識として公開**というFDE型の開発サイクルを採用します。

### Phase 0：政策・業務の棚卸し

- 政策提言
- 地方議会向け提言
- 国家戦略特区に関する提言
- 地域福祉・子ども食堂等の知見
- GitHub上の実装知見

を、再利用可能な「政策知識資産」として整理します。

### Phase 1：行政・現場の業務分析

業務を、

- 時間
- 頻度
- 定型性
- 判断の重要度
- 個人情報リスク
- AI適合性

で分類します。

### Phase 2：軽量AIプロトタイプ

GIPU提供GGUF量子化モデル等を利用し、ローカル／低コスト環境で、

- 要約
- 文書下書き
- 帳票補助
- 問合せ回答案
- データ分類

を実装します。

### Phase 3：人間による検証

AIの正確性だけではなく、

- 修正率
- 確認時間
- 誤出力
- 見落とし
- 職員の心理的負担
- 利用者への説明可能性

を評価します。

### Phase 4：地域実証

実際の現場で、

> **AI導入前 → AI導入後**

の業務時間・品質・安全性・利用者体験を比較します。

### Phase 5：公共財化

実証結果、設計原則、テンプレート、評価指標、再現手順をGitHub等で公開し、他地域が再利用できる状態を目指します。

## 9. KPI：AIの性能だけを測らない

本プロジェクトの評価軸は、LLMのベンチマークだけではありません。

### 業務KPI

- 1件あたり記録時間
- 月間事務時間
- 帳票作成時間
- 問合せ対応時間
- 引継ぎ時間

### 品質KPI

- 人間による修正率
- 誤情報率
- 再確認率
- 対応漏れ
- 監査可能率

### 人間KPI

- 職員の事務負担
- 対人支援時間
- 新任者の習熟時間
- 現場の継続可能性

### 社会KPI

- 食へのアクセス
- 支援への接続
- 地域内消費
- 寄付・助成の透明性
- 地域参加
- 孤立の予防

### ガバナンスKPI

- AI利用記録率
- 人間承認率
- 権限逸脱件数
- 個人情報インシデント
- データ保持期限遵守率

## 10. 設計原則

### Principle 01 — Human-in-the-Loop

AIは支援者。最終判断は人間。

### Principle 02 — Privacy by Design

「集めてから守る」のではなく、最初から集めない・分離する・短く保持する。

### Principle 03 — Auditability

AIが関与した業務ほど、後から検証できるようにする。

### Principle 04 — Local First

自治体・地域の現場で継続運用できる計算量・費用・運用負担を重視する。

### Principle 05 — Open Knowledge

個別の地域で得た知見を、可能な範囲で再利用可能な知識として公開する。

### Principle 06 — Human Dignity

効率化のために人間を置き換えるのではなく、人間が人間に向き合う時間を増やす。

### Principle 07 — Interoperability

自治体、NPO、地域事業者、既存行政システム等と接続できる標準的な構成を目指す。
